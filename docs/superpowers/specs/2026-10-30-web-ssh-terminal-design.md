# Embedded web SSH terminal

User rejected the native-launcher download/install flow and explicitly approved connecting to their Linux PC through a browser SSH terminal. The PC must already have SSH enabled/reachable. This replaces the normal Terminal UI with an in-app terminal; no client download or custom protocol is used. Credentials and terminal traffic pass through the trusted Messenger server for the active connection; they are not saved or logged. No default OS account, saved server SSH key/agent, app-server shell or automatic connection is permitted.

Use xterm.js in an opaque-origin sandboxed iframe containing only locally vendored scripts/styles and no network transport. Parent UI owns a dedicated same-port secure Socket.IO transport with64KiB packet cap, strict same-origin checks, current JWT/auth-version verification, and socket-bound session identities. Only the owning socket receives output or can input/resize/close/trust host. Account revocation/deletion, logout, close and network disconnect end SSH. Resource limits:1session/socket,2/user,32total;20minute inactivity,60second connect deadline,30second host-confirmation. Input/output bounded with backpressure. Xterm output is untrusted; no HTML rendering, link/clipboard side effects, stored scrollback or command logging.

Connect form accepts literal LAN IPv4, allowed SSH port(default22), SSH username, password or pasted private key+optional passphrase, and optional known SHA256 host fingerprint. Default allowed networks are RFC1918 and no loopback/metadata/public/DNS targets; admin may narrow LAN CIDRs/allowed ports. Loopback is allowed only through explicit non-production QA configuration. HostVerifier never auto-accepts: matching supplied fingerprint, or explicit confirmation of the shown fingerprint for this connection only. Approval happens before SSH sends authentication to the target. No host key database or password persistence is needed.

Existing Messenger, calls/screen sharing, games, recovery and ports3000/3443/3090 stay intact. Terminal can minimise while chat remains usable. Every new connection clears old terminal state and credential fields; refresh does not restore sessions. Connection form clearly states SSH availability and server transit. Old native launcher source/archive remains for already-installed users but is not offered by the normal terminal UI.
