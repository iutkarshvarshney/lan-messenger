# Screen sharing and Linux local terminal

User requested screen sharing and a way to open a terminal for SSH/other commands. Clarification: terminal must run on each user's own PC, and PCs are Linux. Existing calls, sounds, draggable card, chat, games, privacy and ports stay available. Prior session authorization is to implement approved changes directly; no new deployment port or server shell is needed.

Screen sharing runs within an accepted private call. Both peers can choose a screen/window through the browser's native picker and stop sharing independently. A large responsive viewer with fullscreen/minimise and a local preview remain separate from the draggable call card, so chat remains usable. Microphone audio stays separate from display video. A negotiated video transceiver allows replaceTrack start/stop without renegotiating the audio call. Call/session identity and endpoint socket ownership scope every signal; old or unrelated signals cannot change another call. Cancelling a picker or ending a call while capture is pending must stop all acquired tracks and preserve the correct call state. Nothing records or stores the shared screen. Unsupported browser capture gets an honest message; viewers can still watch.

The Linux Terminal action launches the PC's native terminal, not a server/container shell or a browser command proxy. A user-installed, source-visible Python3 launcher registers the exact URL lan-messenger://terminal for that user's desktop. It accepts only this fixed action, never commands, SSH hostnames, passwords or query parameters; opens an installed terminal emulator with fixed arguments and shell=False. No listening service, localhost port, network request, root installation or stored credential is needed. Downloadable archive includes install/uninstall instructions. Browser/desktop may ask to open the registered handler. Keep the one-time installation requirement visible; do not claim success based on a timeout or try to auto-install on another user's machine.

Alternatives: SSH in an embedded web terminal was rejected because user explicitly chose their own local shell. A local web service/PTY would add a listening port and a command transport that this request does not need. The fixed desktop launcher keeps existing local SSH configuration and tools.
